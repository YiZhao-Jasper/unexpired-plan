## A plan can outlive the call that made it

Action-chunking policies predict more actions than they execute immediately. **The Unexpired Plan** uses the remaining actions of a previously computed reference plan to monitor accelerated predictions—without an additional reference forward pass for the check.

1. **Align.** Compare the next executed actions with the same future indices of the saved plan.
2. **Check.** Detect excessive action deviation and near repetition of recent emitted chunks.
3. **Remember.** On a veto, execute the saved reference slice and permanently demote the accelerator for the episode.

## What is in this release?

- A model-independent NumPy implementation of the monitor, action normalization, drift/repetition calibration, on-policy candidate scoring, and paired evaluation.
- Explicit schedule-only, scheduled replay, paid-deviation, and matched-admission baselines.
- Runnable examples and behavioral tests for temporal alignment, reference accounting, persistent demotion, calibration, and evaluation.
- The English project website, original paper figures, paired moving illustration, and four-minute V3 film, maintained in this same repository.

This release implements the core algorithm and evaluation utilities. **The original benchmark checkpoints, complete 114-configuration sweep, accelerator ladders, seed files, and per-episode logs are not bundled.** The reported results below are transcribed from the paper, not measurements generated by running this repository. See the [release scope and paper alignment](research/METHOD.md#release-scope).

## Quick start

Python 3.10 or newer is required. The core has one runtime dependency: NumPy. No GPU, model download, or simulator is needed for the examples.

```bash
git clone https://github.com/YiZhao-Jasper/unexpired-plan.git
cd unexpired-plan
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'

python examples/monitor_trace.py
python examples/calibrate_and_select.py
python -m pytest -q
```

The first example introduces a biased accelerated proposal at call 3. The monitor executes the saved reference slice, moves to a conservative candidate, and keeps that candidate after the next reference refresh. Reference calls remain **0, 5, 10**; the veto does not add a call.

The CLI also emits a JSON trace:

```bash
unexpired-plan --calls 12
```

## Use the monitor

```python
from unexpired_plan import Candidate, MonitorConfig, UnexpiredPlanMonitor

# Each predictor returns an [H, action_dimension] NumPy array in the same
# normalized action coordinates. Costs must be measured on matched hardware.
monitor = UnexpiredPlanMonitor(
    reference=reference_predictor,
    candidates=[
        Candidate("fast", fast_predictor, cost=0.2, mechanism="recompute"),
        Candidate("conservative", conservative_predictor, cost=0.6),
    ],
    config=MonitorConfig(
        horizon=10,
        execution_horizon=2,
        theta=0.15,
        repetition_threshold=calibrated_threshold,
        drift_by_age=calibrated_drift,
    ),
)

decision = monitor.step(observation)
environment.execute(decision.executed)
# Reset the monitor and any stateful predictors at the next episode boundary.
```

The predictor names, observation, environment, and calibration values in this integration sketch are supplied by your policy adapter. The runnable examples above provide complete synthetic predictors. A `repetition_threshold` of `0.0` explicitly disables that veto; calibrate it from unaccelerated reference replay for a deployment using both checks.

See [integration and calibration](research/INTEGRATION.md) for action conventions, lifecycle, candidate selection, and evaluation details.

## Paper-reported results

Success-rate changes are relative to the unaccelerated reference, with **95% paired interval half-widths**. The equivalence margin is ±2 percentage points.

| Policy / benchmark | Reference success | Success-rate change | Effective compute speedup | Within ±2 pp? |
| :--- | ---: | ---: | ---: | :--- |
| Cosmos / LIBERO | 98.2% | +0.1 ± 1.1 pp | 1.55× | Yes |
| π₀.₅ / LIBERO-10 | 97.0% | −0.2 ± 0.9 pp | 1.67× | Yes |
| Diffusion Policy / PushT | 58.0% | +1.2 ± 2.6 pp | 1.75× | **Undecided** |
| 3D Diffusion Policy / MetaWorld | 94.2% | +0.1 ± 1.4 pp | 3.09× | Yes |
| Diffusion Policy / ManiSkill3 insertion, held out | 71.3% | −0.2 ± 1.2 pp | 1.96× | Yes |

The original four families use 1,500 paired episodes each. The held-out insertion evaluation uses 6,000 paired episodes after freezing the design. At 1.96× effective compute speedup, speed-matched step reduction changes success by −3.9 pp; the monitored arm changes it by −0.2 ± 1.2 pp. Keeping the reference schedule but removing monitoring yields −6.7 pp at 2.09×.

On three of the original four families, the reference schedule alone is already within the margin. PushT remains undecided. All reported closed-loop evaluations are in simulation. **Compute speedup is not task-duration speedup, peak latency, energy savings, or a safety guarantee.**

Machine-readable values: [`research/reported_results.json`](research/reported_results.json). Protocol and missing reproduction inputs: [`configs/paper_protocol.json`](configs/paper_protocol.json).
